1.3 Хід роботи

Було розроблено повну документацію Vision & Scope для програмної системи
ведення голосового польового журналу з апаратним підтвердженням запису
(«Notes-On-Walk»). Документ охоплює аналіз проблеми польової звітності, бізнес-
вимоги, концепцію рішення, деталізовані рамки першого та наступних випусків, а
також робоче середовище системи.
Основна ідея проєкту полягає в усуненні бар’єра між виконанням фізичної
роботи спеціалістом (монтажником, будівельником, інженером) і внесенням
структурованих записів до журналу. Замість ризикованої взаємодії з сенсорним
екраном смартфона в рукавицях чи за наявності бруду, працівник здійснює запис
за парадигмою Push-to-Talk за допомогою захищеного апаратного пульта на базі
Raspberry Pi.
У процесі роботи проведено порівняльний аналіз наявних ринкових рішень
(Antimattr Mnemosyne, Plaud Note, Rabbit r1, будівельних журналів Fieldwire і
Procore) і виявлено їхні недоліки: офісний формфактор диктофонів, відсутність
прив’язки до промислових об’єктів та фотофіксації або необхідність повного
ручного введення даних на сенсорних екранах. Сформовано концепцію гібридного
B2B SaaS-рішення, де велика мовна модель (LLM) разом зі Speech-to-Text (Whisper)
вилучає з неструктурованого мовлення тріаду ключових сутностей: виконану дію,
цільовий об’єкт та наступний крок.
Деталізовано архітектуру комплексу, яка включає серверну частину на базі
Python (FastAPI) та СУБД PostgreSQL, IoT-клієнт на Raspberry Pi з Python-скриптом
обробки сигналів GPIO, мікрофона та світлодіодної індикації, мобільний застосунок
Android на Kotlin із функціями зчитування QR-кодів об’єктів, фотофіксації
та офлайн-буферизації (Room), а також вебклієнт для перевірки чернеток та
адміністрування. Визначено функціональні вимоги первинного випуску (FE-1 – FE-16) та наступних релізів (FE-17 – FE-28). Повний опис проєкту у форматі Vision & Scope наведено у додатку В.
1.4 Висновки

Розроблено концептуальний документ Vision & Scope, який визначає бізнес-рамки, функціональні межі та технічне бачення програмної системи ведення голосового польового журналу з апаратним підтвердженням запису.

1. БІЗНЕС-ВИМОГИ

1.1. Передумови

Програмний продукт створюється для сфери будівництва, монтажних та
ремонтних робіт, виїзного технічного обслуговування й інженерного нагляду.
Предметною областю є оперативне фіксування та структуризація робочих операцій
безпосередньо на робочому місці без постійного використання сенсорного екрана
смартфона.
Традиційні підходи до польового ведення журналів мають низку критичних
проблем:
– Незручність ручного введення: робота в захисних рукавицях, наявність
виробничого пилу та бруду унеможливлюють взаємодію з сенсорними
дисплеями.
– Ризик пошкодження техніки: постійне витягування телефону на
риштуваннях або висотних конструкціях призводить до його падіння та
розбиття.
– Інформаційний шум звичайних диктофонів: сирий аудіозапис вимагає
тривалого ручного прослуховування, позбавлений прив’язки до локацій і
не формує звітних карток.
– Втрата даних: через відкладання записів на кінець зміни робітники
забувають до 30–40% деталей (витрата кріплень, дефіцит кабелю,
черговість кроків).
Система покликана усунути бар’єр між фізичною дією на об’єкті та цифровим
обліком, забезпечуючи миттєву фіксацію голосом та автоматичне вилучення
сутностей за допомогою ШІ.

1.2. Бізнес-можливості

Найближчим концептуальним аналогом є апаратний проєкт Antimattr (Project
Mnemosyne, акселератор Y Combinator), який створює голосовий апаратний
термінал для взаємодії з ШІ-агентами. Споживчі пристрої Plaud Note та
Limitless Pendant також використовують фізичну кнопку для запису зустрічей та
конспектування. Проте офісні диктофони позбавлені промислового захисту, не
мають механізмів локальної прив’язки до будівельних конструкцій та фотофіксації.
Спеціалізовані будівельні журнали (Fieldwire, Procore) забезпечують
надійний облік, але спираються суто на текстовий ручний ввід через екран
смартфона, що незручно на об’єкті.
Розроблювана система поєднує переваги фізичного пульта Push-to-Talk і
аналітичні можливості хмарних LLM для польового журналу. Порівняння наведено

2. КОНЦЕПЦІЯ РІШЕННЯ

2.1. Окреслення концепції

Програмна система ведення голосового польового журналу «Notes-On-
Walk» - це апаратно-програмний комплекс, призначений для швидкого фіксування
виробничих дій польовим персоналом за допомогою фізичного пульта Push-to-Talk,
збагачення контексту даними маркування (QR) та фотофіксації через смартфон, а
також інтелектуального перетворення неструктурованого мовлення у формалізовані
звіти за допомогою LLM із подальшим вебпогодженням.

2.2. Головна функціональність

– MF-1: Апаратне Push-to-Talk захоплення: активація аудіозапису
натисканням фізичної кнопки на пульті, світлодіодна та тактильна
індикація стану;
– MF-2: Локальний захищений міст: передача аудіофайлу на смартфон
через локальний сокет/Bluetooth без прямого виходу пульта в інтернет;
– MF-3: Контекстне маркування об’єкта: автоматичне зв’язування
аудіофайлу зі сканованим QR-кодом зони та контрольною фотографією з
камери смартфона;
– MF-4: Офлайн-буферизація подій: ізольоване накопичення сформованих
пакетів у внутрішній БД смартфона за відсутності покриття зв’язку;
– MF-5: Автоматична хмарна синхронізація: фонове пакетне вивантаження
накопичених звітів на Web API через захищений канал HTTPS;
– MF-6: ШІ-структурування мовлення: транскрипція мови (STT) та
екстракція JSON-об’єкта з тріадою: виконана дія, цільовий об’єкт,
наступний крок;
– MF-7: Інтерфейс верифікації чернеток: вебпанель менеджера для
прослуховування аудіо, перевірки фото та затвердження звіту в один клік;
– MF-8: Пошуковий індекс та архів: повнотекстовий пошук за об’єктами,
експорт журналів робіт у форматах CSV/PDF.

3. РАМКИ ТА ОБМЕЖЕННЯ ПРОЄКТУ

3.1. Опис функціональності серверної частини та ІоТ-клієнта

У межах первинного випуску реалізуються серверна частина з бізнес-логікою
та IoT-клієнт на Raspberry Pi. Клієнтські інтерфейси емулюються тестовими
сценаріями та базовими REST-запитами.
Серверна частина (Back-end / Web API):
– FE-1: Автентифікація та авторизація користувачів за схемою JWT (ролі:
робітник, менеджер, адмін);
– FE-2: Прийом пакетів польових даних (аудіо, фото, метадані, ID об’єкта)
за протоколом HTTPS;
– FE-3: Збереження медіафайлів у файловому сховищі з генерацією
унікальних хеш-ідентифікаторів;
– FE-4: Інтеграція зі стороннім API транскрипції мовлення (OpenAI
Whisper);
– FE-5: Інтеграція з мовною моделлю (LLM) для вилучення полів: дія,
об’єкт, наступний крок у форматі JSON;
– FE-6: Збереження структурованих записів у PostgreSQL зі статусами
«Чернетка», «Погоджено», «Відхилено»;
– FE-7: REST API управління чернетками: зміна статусу, ручне коригування
розпізнаних полів;
– FE-8: Пошуковий індекс та фільтрація робіт за датами, об’єктами,
виконавцями та статусами;
– FE-9: Адміністрування: керування акаунтами, журналами запитів та
резервним копіюванням бази даних;
– FE-10: Локалізація системних повідомлень API українською та
англійською мовами.
IoT-клієнт (Апаратний помічник на Raspberry Pi):
– FE-11: Опитування контактів GPIO: детекція утримання кнопки Push-to-
Talk та сенсора дотику;
– FE-12: Захоплення моно-аудіопотоку з мікрофона в режимі реального
часу, збереження у форматі .wav;
– FE-13: Світлодіодна індикація станів: черговий режим, активний запис,
запис збережено, помилка;
– FE-14: Генерація тактильного сигналу підтвердження фіксації за
допомогою вібромотора;
– FE-15: Локальний мережевий сервер для захищеної передачі аудіофайлу
на смартфон (Wi-Fi/Bluetooth);
– FE-16: Програмний таймер захисту від випадкового затискання кнопки
(обмеження запису до 60 секунд).

3.2. Опис функціональності веб клієнта та мобільного клієнта

Мобільний клієнт (Android / Kotlin):
– FE-17: Авторизація працівника та вибір активної робочої зміни;
– FE-18: Локальне з’єднання з пультом Raspberry Pi та прийом звукових
доріжок;
– FE-19: Сканування маркувальних QR-кодів об’єктів за допомогою камери
смартфона;
– FE-20: Модуль контрольної фотофіксації виконаної роботи (CameraX);
– FE-21: Офлайн-буфер на базі Room (SQLite) з чергою гарантованої
доставки пакетів;
– FE-22: Фоновий сервіс синхронізації з Web API після відновлення зв’язку;
– FE-23: Мобільний інтерфейс швидкого перегляду власних створених
чернеток за день (з підтримкою перемикання української та англійської
локалізацій).
Вебклієнт (Адміністрування та моніторинг):
– FE-24: Інтерактивний дашборд виконаних робіт із групуванням за зонами
та бригадами;
– FE-25: Робоче місце бригадира з вбудованим плеєром оригінального аудіо
та переглядом фото;
– FE-26: Форма редагування та фінального погодження чернеток;
– FE-27: Модуль аналітики простоїв та вивантаження зведених звітів робіт
у форматі CSV/PDF;
– FE-28: Панель системного адміністратора для управління правами
доступу та глобальними налаштуваннями локалізації системи (UA/EN).

4. БІЗНЕС-КОНТЕКСТ

4.3. Опис програмних засобів та програмних інструментів, які будуть
використані у проекті

Система складається з чотирьох інтегрованих частин: серверного Web API,
апаратного пульта Raspberry Pi, мобільного шлюзу на Android та вебінтерфейсу.
– IoT-рівень: Raspberry Pi OS (Linux), мова Python 3.11+, бібліотеки
«RPi.GPIO» для роботи з портами вводу/виводу, «sounddevice»/«pyaudio»
для опрацювання звуку, стандартна бібліотека «socket».
– Мобільний рівень: ОС Android (API 26+), середовище Android Studio,
мова Kotlin, Android Jetpack, бібліотеки CameraX, ZXing (QR-сканер),
Room Persistence Library, Retrofit2/OkHttp.
– Серверний рівень: Python 3.14+, вебфреймворк FastAPI (REST, JSON),
СУБД PostgreSQL 18 для реляційних даних, Docker і Docker Compose для
контейнеризації та розгортання.
– ШІ-сервіси: OpenAI Whisper API (перетворення аудіо на текст), OpenAI
GPT-4o-mini API (семантичний аналіз тексту за промтом із валідацією
JSON-схеми).
– Веб-рівень: TypeScript, фреймворк SvelteKit, Tailwind CSS.
